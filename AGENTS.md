# Project Instructions

## UI skill guidance

For tasks that create, change, review, audit, or polish rendered UI in this repository, evaluate the task and invoke one or more of these installed skills when their expertise is useful:

1. `design-taste-frontend`
2. `impeccable`
3. `emil-design-eng`

Do not automatically invoke all three for every UI edit. Select the smallest relevant set based on the task, and combine skills when the work spans multiple responsibilities. UI work includes HTML and Liquid templates, CSS, browser-facing JavaScript, components, layouts, responsive behavior, accessibility, visual assets, interaction states, and motion.

Choose them according to these responsibilities:

- Use `design-taste-frontend` for new pages, portfolios, redesign direction, visual composition, anti-template discipline, and broad frontend pre-flight review.
- Use `impeccable` for UX critique, interface refinement, accessibility, responsiveness, production hardening, and visual QA.
- Use `emil-design-eng` for components, interaction polish, purposeful motion, easing, timing, tactile feedback, and animation performance.

When one or more skills are selected:

1. Read each selected skill's complete `SKILL.md` and follow its setup and referenced playbook requirements.
2. Inspect the existing interface and at least one source of visual truth such as tokens, CSS, templates, or assets.
3. Preserve the established brand, information architecture, copy, routes, accessibility behavior, and user changes unless the user explicitly requests otherwise.
4. Follow any analysis, design-read, quality-check, and output requirements imposed by the selected skills.

Before finishing UI work:

1. Apply the required checks from every selected skill.
2. Verify desktop and mobile behavior together, including keyboard access, reduced motion, contrast, overflow, and interaction states.
3. Keep motion purposeful and prefer transform and opacity for animation.
4. If a relevant selected skill is unavailable, report that limitation and continue with the best applicable guidance.

User instructions and factual project requirements take precedence. When selected skills recommend different treatments, preserve usability, accessibility, existing brand consistency, and the user's stated direction first, then use the skill with the most specific responsibility listed above.
